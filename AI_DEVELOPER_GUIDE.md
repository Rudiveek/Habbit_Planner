1. Project Overview
   1.1 Introduction

Habit Planner is not a simple habit tracking application.

It is a Personal Growth Platform designed to help users manage every important aspect of their daily life from a single application.

The goal is to create one place where users can plan, track, analyze, and improve themselves consistently.

The platform combines:

Daily Habits
Food & Nutrition
Physical Fitness
Calendar Planning
Productivity
Analytics
Progress Tracking
Personal Goals

Instead of switching between multiple apps for habits, workouts, food, calendars, and productivity, the user should be able to manage everything inside one application.

1.2 Vision

The vision of Habit Planner is to become a Personal Operating System (Personal OS).

The application should feel like:

Apple Health
Notion
Linear
Hevy
GitHub Contributions
Google Calendar

combined into one beautiful and easy-to-use platform.

The focus is simplicity, consistency, and productivity.

1.3 Goals

The primary goals of this project are:

Goal 1

Help users build consistent habits.

Goal 2

Track food, nutrition, and water intake.

Goal 3

Track physical fitness and workouts.

Goal 4

Allow planning using:

Daily Planner
Weekly Planner
Monthly Planner
Goal 5

Provide beautiful analytics and progress tracking.

Goal 6

Become a portfolio-quality software engineering project.

1.4 Target Users

Habit Planner is designed for:

Students
Gym enthusiasts
Professionals
Developers
Anyone interested in self-improvement

Render / Vercel 3. Development Rules

These rules are mandatory.

Rule 1

Never create another project.

Always continue working on the existing project.

Rule 2

Never change the existing architecture without permission.

Rule 3

Never redesign any page unless the user explicitly asks.

Rule 4

Before writing code:

Analyze the existing project.
Understand the current implementation.
Tell the user which files will change.
Wait for approval.

Only then generate code.

Rule 5

Always generate complete files.

Never generate snippets.

Never say:

"Add this below..."
"Replace these lines..."
"Insert this here..."

Always provide the complete updated file.

Rule 6

Generate one feature at a time.

Never generate multiple unrelated features in one response.

Rule 7

Never assume a feature already exists.

Clearly distinguish between:

Existing features
Planned features
Rule 8

Follow the existing folder structure.

Do not reorganize folders unless requested.

Rule 9

Write clean, reusable React components.

Avoid duplicate code.

Rule 10

Always wait for user confirmation before moving to the next file.
